# Contributing

Updated 2026-09-20.

## Work in the correct project

Read [README](README.md), [architecture](ARCHITECTURE.md), [project status](PROJECT_STATUS.md), and [known issues](KNOWN_ISSUES.md) before changes. `frontend/` is the admin command center. `../employee-workspace-portal/` is a separate employee app. Preserve unrelated local edits.

Edit React source under `frontend/src/`; do not hand-edit hashed files under `frontend/dist/assets/`. Build output is regenerated by Vite. Preserve backend authorization checks and use server shift/anomaly/billing values.

## Validation

Build the command center:

```powershell
npm --prefix frontend run build
```

From `backend/`, with dependencies and `httpx` installed, run each suite in a separate process so its module-level temporary database setup is isolated:

```powershell
python -m unittest test_integration -v
python -m unittest test_chief_signup -v
```

From the sibling employee portal, use `npm run build` and `npm test` after installing dependencies and Playwright Chromium. Its tests mock API/socket responses; they do not replace live integration checks. For visual changes check desktop/mobile layouts, keyboard access, error/empty states, and appropriate role actions.

Record what actually ran and distinguish mocked checks from live tests. Do not mark unverified risks as reproduced defects.

## Data and deployment

Docker and native SQLite databases are separate. Inspect the intended database before changes, take a SQLite-consistent backup, and scope cleanup to identified records plus dependencies. Preserve legitimate users, workspaces, and credentials. Database files and backups are ignored by Git and must not be committed.

After an authorized local frontend deployment:

```powershell
docker compose up -d --build --no-deps frontend
```

Update the affected Markdown documents when behavior, setup, validation, or operational data changes. Keep API contracts in [INTEGRATION_REPORT.md](INTEGRATION_REPORT.md) and employee lifecycle guidance in [EMPLOYEE_APP_HANDOFF.md](EMPLOYEE_APP_HANDOFF.md).

## Snapshot/demo validation

Run `python -m unittest test_demo -v` from `backend/` in its own process, alongside the existing isolated suites. The portal's `tests/demo.spec.js` covers toggling demo, time/CPU submission, immediate termination, snapshot display/search, responsive layout, and disabling the override.

Preserve real `created_at` timestamps; do not invent legacy times or substitute demo time for wall-clock audit time. Keep `DEMO_MODE` gating, instance authorization, CPU bounds, and shared scheduler/API clock behavior intact. Snapshot card components/styles are duplicated across the two apps and should remain aligned.
